# Photomatch

## アカウント運用

ログインアカウントの権限（`profiles.role`）は1アカウントにつき1つで、`client`（お客様）/ `photographer`（カメラマン）/ `ops`（運営）のいずれか。1つのアカウントを複数の権限で兼ねることはできない。

| 用途 | ログイン画面 | 備考 |
|---|---|---|
| お客様 | `login.html` | 新規登録は誰でも可 |
| カメラマン | `pro-login.html` | 運営画面（`ops.html`）の「カメラマン登録」で作成して渡す。本人のセルフ登録も可 |
| 運営 | `ops-login.html` | 下記の手順で権限を付ける |

### 運営アカウント

- 運営用: `info.photomatch@gmail.com`（`ops`）。審査・送金確定・カメラマン登録に使う
- 動作確認用のカメラマンアカウント（`photographer`）は、運営者の個人メールアドレスで別に作成済み。管理画面（`admin.html`）の時間枠・振込先口座の確認に使う。メールアドレスは、リポジトリには記載しない

運営アカウントの作り方:

1. `login.html` から新規登録し、確認メールのリンクを開く
2. Supabase の SQL Editor で権限を付ける

```sql
update profiles set role = 'ops' where email = 'info.photomatch@gmail.com';
```

`profiles` はブラウザ（anon / authenticated）から更新できない設計。権限の変更は、SQL Editor または service_role からのみ行う。

### カメラマンの登録から公開まで

1. 運営が `ops.html` の「カメラマン登録」でアカウントを作り、メールアドレスと仮パスワードを本人に渡す（作成直後のプロフィールは非公開）。仮パスワードを紛失した・ログインできない場合は、同じ画面の「仮パスワードの再発行」で新しいものを発行できる（カメラマンのアカウントのみ対象。以前のパスワードは使えなくなる）
2. 本人が `pro-login.html` からログインし、管理画面（`admin.html`）の「プロフィール設定」で、写真・表示名・エリア・性別・ひとこと・紹介文・Instagram・英語対応を入力する。時間枠と振込先口座もここで設定する
3. 運営が `ops.html` の「カメラマンの掲載管理」で内容を確認し、「承認して公開する」を押す
   - 写真・表示名・エリア・性別・紹介文がそろっていないと公開できない（サーバー側でも確認）
   - 料金プランが未登録なら、公開時に標準の4プラン（`js/data.js` の `PRICING_PLANS`）を登録する。個別の料金にしたい場合は SQL Editor で `plans` を編集する

### 公開・非公開の仕組み

検索・予約に出るのは、次の2つを両方満たすときだけ。

| フラグ | 意味 | 変更できる人 |
|---|---|---|
| `is_visible` | 運営の承認（掲載の許可） | 運営のみ（掲載管理画面。`/api/photographers/visibility` 経由） |
| `is_paused` | 本人による一時休止 | 本人（管理画面の「予約受付を一時休止する」） |

運営が掲載を停止（`is_visible = false`）した場合、本人は再開できない。本人の休止中も、すでに入っている予約はそのまま。

本人が編集できるのは `name / area / gender / bio / price_comment / instagram / speaks_english / bio_en / price_comment_en / photo_url / is_paused` だけ（`supabase/schema.sql` の列単位の grant）。承認・評価・レビュー数などは運営のみ。写真は公開バケット `photographer-photos` の自分のフォルダに置かれる。

### 口コミ（撮影後レビュー）

- お客様がマイページの予約カードから投稿する（星1〜5・コメント・表示名。表示名は任意で、未入力は「匿名のお客様」）。投稿後も編集・削除できる
- 投稿できるのは、**自分の予約**で、**撮影の終了時刻（JST）を過ぎた**、キャンセルされていない予約に限り、**1予約につき1件**。この条件は画面ではなく DB（`reviews` の RLS）で強制している
- カメラマンの評価・レビュー数は、投稿・編集・削除・非表示のたびに DB のトリガー（`reviews_refresh_rating`）が `reviews` から自動で計算する。手で書き換えない
- 不適切な口コミは、運営画面の「口コミの管理」で非表示にできる（`/api/reviews/moderate` 経由）。非表示にすると、公開ページから消え、評価の集計にも入らない。投稿者本人には「運営により非表示」と表示される
- トップページの「利用者の口コミ」（`js/data.js` の `TESTIMONIALS`）は、実在のお客様の許可を得た口コミだけを手で入れる。空の間は欄ごと非表示になる

## お金の流れ（決済・キャンセル・報酬）

金額の計算はすべて `js/data.js` にまとめてあり、画面とサーバー（`functions/`）が同じ関数を使う。

### 決済
- お客様は予約時に全額をクレジットカードで支払う（Stripe Checkout。コンビニ払いなどの後払い型は使わない）。予約は Stripe の Webhook を受けて「確定」になる
- 価格は税込表示のため、Stripe Tax（自動税計算）は使わない

### お客様都合のキャンセル（マイページ → `/api/bookings/cancel`）
| 時期（日本時間） | キャンセル料 | カメラマンへの補償 |
|---|---|---|
| 撮影日の3日前まで | 0円 | なし |
| 2日前 | プラン料金の50% | なし |
| 前日 | プラン料金の100% | なし |
| 当日（撮影開始前） | プラン料金の100% | ¥2,000 |

- オプション料金はキャンセル料の対象外で、常に全額返金する
- 返金は Stripe で自動。失敗したときは、運営宛てのメールの件名に「要返金対応」と入るので、Stripe の管理画面から手動で返金する
- 撮影開始時刻を過ぎた予約は、マイページからはキャンセルできない（問い合わせで個別対応）
- **遅刻キャンセル**：お客様が集合時間に15分以上遅れた場合（規約第5条）は、運営画面「予約の管理」（または「カメラマンへの送金」）の「遅刻キャンセル」で処理する（`/api/bookings/no-show`）。撮影開始後〜送金前まで可能。当日キャンセルと同じく、プラン料金をいただき、オプション分を返金し、カメラマンの報酬は補償の¥2,000になる。お客様・カメラマン・運営にメールが届く
- カメラマン側の都合・悪天候などは、運営画面「予約の管理」の「キャンセル（返金）」で処理する（`/api/bookings/ops-cancel`。理由と返金額を選び、Stripe で返金、カメラマンの報酬はなし、3者にメール）
- 自動返金に失敗したら、Stripe の管理画面で手動返金し、「予約の管理」の「手動で返金済みにする」を押す（Stripe からの通知でも自動で反映される）

### カメラマン報酬（`photographerPayoutFor`）
- 撮影した予約：**プラン料金の50% ＋ オプション1件につき¥1,100**
- 当日キャンセル・遅刻キャンセル：補償の¥2,000のみ
- 運営画面の「カメラマンへの送金」に、カメラマンごとの合計と振込先が出る。実際の振込は運営が銀行で行い、画面では「振込済み」を記録するだけ（記録するとカメラマンに明細メールが届く）
- 撮影分を送金できる条件：**納品済み**／撮影日から30日の保証期間が過ぎている／マッチング数保証の申請中でない（申込み済みなら申請期限が過ぎている）／送金の保留中でない。当日キャンセル補償はすぐに送金できる
- **送金の保留**：チャージバック（不審請求の申し立て）や、Stripe の管理画面での返金があると、Webhook が自動で保留にし、運営にメールが届く。確認後、「予約の管理」で解除する
- 無料再撮影（¥0）は報酬の対象外

### モニター価格
- 応募があると運営にメールが届く。運営が「当選」にすると、応募者に結果のメールが届く（落選も同様）
- 定員は先着10名（`MONITOR_CAPACITY` と `monitor_slots_left()`）。定員に達すると応募フォームが締め切られ、運営もこれ以上当選にできない
- 当選者がスタンダードかスマホプランを予約すると、決済時に半額が自動で適用される（1回限り。キャンセルした場合は再び使える）
- モニター予約のカメラマン報酬も「実際のプラン料金（半額）の50%」で計算する

## セキュリティの前提（変更するときの注意）

- **役割（`profiles.role`）はブラウザから決められない。** 新規登録の `handle_new_user` は、`client` と `photographer` だけを受け付け、それ以外（`ops` など）は `client` にする。運営アカウントは SQL Editor で `update profiles set role = 'ops' where email = '…'` として作る
- **プラン（`plans`）の価格・内容はブラウザから書き換えられない**（読み取りのみ）。決済額はこのテーブルの `price`。変更は SQL Editor か、運営の「承認して公開する」（標準プランの自動登録）から行う
- **マッチング数保証（`guarantee_claims`）** は、DB のトリガー（`guarantee_claims_guard`）が、お客様の書き込みを「申請（状態は `applied` 固定、申請できる日は予約日＋30日をDBが計算）」と「申請中 → 申請済みへの変更（申請できる日以降）」だけに絞る。審査（承認・却下）は運営だけ
- **チャットの `sender_role`・既読** は、自分の立場（お客様なら `client`、カメラマンなら `pro`）の分しか書けない
- お客様が入力した文字（予約名など）を `innerHTML` に入れるときは、必ず `escapeHtml`（`js/util.js`）を通す
- **決済ページの有効期限は31分、決済待ちが枠を押さえる時間は35分**（`js/data.js` の `CHECKOUT_EXPIRES_MIN` / `PENDING_PAYMENT_HOLD_MIN` と、`schema.sql` の `booking_slots` を同じ値にする）。それでも期限後に決済された場合（同じ枠が先に埋まっていた、キャンセル済みだった）は、Webhook が予約を取り消して全額返金し、運営にメールで知らせる

## シフト（予約を受け付ける時間）

- **初期状態はすべて休み。** お客様が予約できるのは、カメラマンが管理画面のシフトで「受付中（○）」にした30分枠だけ（`shifts` に `is_open = true` の行がある枠）。行がない枠は休み
- カメラマンの管理画面は、予約を受け付ける30日分を表示する。1枠ずつのタップのほか、「時間帯 × 曜日」で一括して開ける・休みにする機能がある
- 45分プランは、連続する2枠（30分 × 2）が開いている開始時刻だけ予約できる
- 枠の判定は `js/availability.js` に1つだけあり、予約画面・日程変更画面・サーバー（`functions/_lib/slots.js`）が同じものを使う
- 新しく登録したカメラマンは、承認して公開しても、シフトを開けるまで予約を受けられない

## 日程変更（あんしん振替プラン）

お客様がマイページの「日程変更」から、同じカメラマン・同じプランで日時だけを動かす（`/api/bookings/reschedule`、判定は `js/data.js` の `rescheduleQuote`）。

| 時期（日本時間） | 条件 |
|---|---|
| 撮影日の3日前まで | 誰でも無料。回数の制限なし |
| 2日前〜撮影開始前 | 「あんしん振替プラン」加入者だけ、1回まで無料 |
| 上記以外・撮影開始後 | 日程変更はできない（キャンセル規定どおりのキャンセル。開始後はお問い合わせ） |

- 変更先は、予約と同じ判定（カメラマンが開けた空き枠・予約可能な30日の範囲）。自分の元の枠と重なる動かし方もできる
- 変更すると、お客様・カメラマン・運営にメールが届く。変更前の日時は `previous_booking_date` / `previous_start_time` に残る
- 送金の保証期間（30日）は、変更後の撮影日から数える
- 悪天候・カメラマン都合などで、運営がお客様の代わりに日程を動かすときは、運営画面「予約の管理」の「日程変更」を使う（料金・回数の制限はかからない）

## お客様の性別（異性スタッフ写真セレクト）

- 新規登録（ログイン画面・予約画面）で、性別（男性／女性／回答しない）を必須で選ぶ。`profiles.gender` に保存する（ブラウザからは書き換えられない）
- 予約時の性別は `bookings.customer_gender` に残り、運営宛ての予約メールに「依頼者の性別」として載る
- 「異性スタッフ写真セレクト」は、男性または女性を選んだお客様だけが選べる（画面とサーバーの両方で確認）
- 運用：納品があると、運営宛てのメールに「異性スタッフ写真セレクトあり（女性／男性スタッフが選ぶ）」と出る。担当スタッフがアルバムから一枚を選び、運営画面「予約の管理」の「おすすめを送る」で、どの写真か・選んだ理由を送る（`/api/bookings/staff-pick`）。お客様にメールが届き、マイページにも表示される。未送信の予約は「要対応」に並ぶ
- 登録済みで性別が未設定のお客様は、このオプションを選ぶとき、または予約のときに入力する

## 本人確認・接客研修（「審査済」バッジ）

- 運営が、カメラマンを**初めて**公開するとき、「本人確認と接客研修は完了していますか？」の確認が出る。OK を押すと `photographers.verified_at` に日時が入る（`/api/photographers/visibility`）
- サイトの「審査済」「審査済カメラマン」バッジは、`verified_at` があるカメラマンにだけ表示する。確認済みのカメラマンを再公開するときは、確認は出ない
- すでに公開されていたカメラマンは、`schema.sql` の実行時に確認済みとして印を付ける（デモ用の p3〜p6 を除く）

## 納品

- カメラマンが撮影後、管理画面の予約から「納品する」で写真のアルバムのリンク（https）を登録する（`/api/bookings/deliver`）。お客様にメールが届き、マイページに「撮影データを見る」が出る。運営にも通知が届く
- 納品期限は、撮影日から3営業日（スピード納品は翌営業日）。土日・祝日（`JP_HOLIDAYS`。2028年以降は追記が必要）を除く。期限を過ぎるとカメラマンの画面に赤字で出る
- 送金は納品済みの予約だけ

## マッチング数保証（無料再撮影）

1. お客様が撮影後、マイページで申し込む（申請できる日は撮影日＋30日をDBが計算）
2. 申請できる日から**14日間**のうちに、マイページから「無料再撮影を申請する」。運営にメールが届く
3. 運営が「マッチング数保証・再撮影補償の審査」で承認／却下（`/api/guarantee/review`）。お客様に結果のメール、承認ならカメラマンにも知らせる
4. 承認されたお客様は、マイページの「再撮影の日程を選ぶ」から日時を選ぶ（`/api/guarantee/reshoot`）。同じカメラマン・同じプランの ¥0 の予約ができ、通常の予約と同じメールが届く。キャンセル・日程変更も通常の予約と同じ
- 申し込み済みの予約は、申請期限が過ぎるまで（申請したら審査が終わるまで）送金しない。承認しても元の撮影の報酬は払う（再撮影の分の報酬はなし）

## Stripe Webhook の設定

Stripe の管理画面 → 開発者 → Webhook（イベントの送信先）で、送信先 `https://photo-match.jp/api/stripe/webhook` に、次のイベントを登録する（本番モード・テストモードそれぞれ）。

- `checkout.session.completed` / `checkout.session.expired`
- `charge.refunded`
- `charge.dispute.created` / `charge.dispute.closed`

## CSS / JS を変更したら（キャッシュ対策）

`css/` や `js/` を変更したら、コミット前に次を実行する。

```
node scripts/stamp-assets.mjs
```

各 HTML の CSS/JS の URL に内容ハッシュ（`?v=…`）と import map を付け直す。これを忘れると、ブラウザに残った古い CSS / 翻訳ファイルと新しい HTML が組み合わさり、「top.hero.cta」のような翻訳キーがそのまま表示されたり、画像が巨大になったりする（`scripts/build-articles.mjs` を実行した場合は自動で行われる）。

あわせて `_headers` で HTML/CSS/JS を毎回再検証（`no-cache`）にしている。Cloudflare の「キャッシュ → 設定 → ブラウザキャッシュ TTL」は「既存のヘッダーを尊重する」にしておくこと。
